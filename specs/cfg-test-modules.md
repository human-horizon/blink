# Пропуск cfg(test)-модулей

## Контекст

`bevy_ecs` содержит большой `#[cfg(test)] mod tests { ... }`. После синтаксического разбора основной библиотеки checker пытается анализировать тестовый код, который не входит в обычную библиотечную конфигурацию и содержит множество неподдерживаемых конструкций.

## Цель

Распознавать атрибут `cfg(test)` непосредственно перед модулем и пропускать весь этот модуль как отключённый в обычном режиме проверки.

## Что изменится

1. `internal/parser/parser.go` — распознавание `cfg(test)` и пропуск inline-модуля.
2. `internal/parser/parser_test.go` — регрессионные тесты.

## Детали реализации

1. `skipAttributes` возвращает признак найденного `test` внутри атрибута `cfg`.
2. Перед объявлением `mod` с этим признаком пропускать тело сбалансированных фигурных скобок.
3. Поддержать `pub mod` и внешнее `mod name;` в отключённой конфигурации.
4. Не включать cfg-логику для других условий на этом шаге.

## Критерии приёмки

- [ ] `#[cfg(test)] mod tests { неподдерживаемый_код }` не ломает обычную проверку.
- [ ] `#[cfg(test)] pub mod tests;` пропускается.
- [ ] Незавершённое тело модуля даёт ошибку.
- [ ] Обычные модули продолжают проверяться.
- [ ] Все тесты, `go vet` и `go build` проходят.
