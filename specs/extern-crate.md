# Объявления `extern crate`

## Контекст

После поддержки Cargo-layout, атрибутов и glob-импортов `bevy_ecs` останавливается на `extern crate std;`. Текущий парсер не распознаёт объявления внешних crate.

## Цель

Распознавать декларативный синтаксис `extern crate name;` и `extern crate self as name;`, не пытаясь пока загружать внешние Cargo-зависимости.

## Что изменится

1. `internal/ast/ast.go` — узел объявления внешнего crate.
2. `internal/parser/parser.go` — разбор `extern crate` с опциональным alias.
3. `internal/parser/parser_test.go` — регрессионные тесты.
4. `internal/checker/checker.go` — игнорирование декларации на этапе проверки внешних зависимостей.

## Детали реализации

1. Распознавать `extern` и `crate` как идентификаторы, поскольку они пока не являются ключевыми словами lexer.
2. Принимать имя crate и форму `self as alias`.
3. Требовать завершающую `;`.
4. Не создавать фиктивные типы, функции или модули для внешнего crate.
5. Другие формы `extern` должны выдавать диагностическую ошибку.

## Критерии приёмки

- [ ] `extern crate std;` разбирается.
- [ ] `extern crate self as bevy_ecs;` разбирается.
- [ ] Декларации не ломают checker.
- [ ] Некорректное объявление отклоняется.
- [ ] Все тесты, `go vet` и `go build` проходят.
