# Строгая проверка match-выражений

## Контекст

Парсер распознаёт `match`, но возвращает искусственный идентификатор `<match>`.
Checker затем сообщает `cannot find value <match>`, вместо проверки сопоставления
и типов тел ветвей.

## Цель

Представить `match` в AST и проверять его как Rust-выражение: проверять scrutinee,
паттерны, bindings и совместимость типов всех arm bodies.

## Детали

- Добавить в AST `MatchExpr` и `MatchArm`.
- Парсер сохраняет scrutinee, паттерны и тела arm; тела в `{}` становятся блоками,
  остальные — выражениями.
- Checker проверяет scrutinee, создаёт отдельное окружение для каждого arm,
  проверяет pattern bindings и требует одинаковый тип результатов arms.
- Wildcard и irrefutable patterns не создают лишних ошибок; exhaustiveness analysis
  остаётся отдельной задачей.
- Несовместимые типы arm bodies — диагностическая ошибка по строгим правилам Rust.

## Приёмка

- [ ] Ошибка `cannot find value <match>` исчезает для валидного match.
- [ ] Биндинги паттернов доступны только внутри своего arm.
- [ ] Несовместимые типы arm bodies отклоняются.
- [ ] Все существующие тесты проходят.
- [ ] `go vet ./...`, `go build ./...` и Bevy-проверка проходят.
- [ ] Не добавляются Bevy-specific wildcard-правила.
