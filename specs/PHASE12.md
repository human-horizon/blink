# Phase 12 — Rust → C Transpiler (TinyCC backend)

## Цель
`blink build <path>` проверяет типы, генерирует C99-подобный код и собирает исполняемый файл через TinyCC. `blink run <path>` запускает результат.

## Выбранные ограничения
- **C**: C99 с расширениями TinyCC (statement-expressions `({ ... })`) — нужны для блоков-выражений Rust.
- **TinyCC**: установлен в `/Users/a/Space/Tools/bin/tcc`.
- **Папка сборки**: `<path>/build/` внутри входной директории, бинарь `out`.
- **Подмножество Rust**: всё, что реализовано в фазах 1–11.

## Общая стратегия
1. Типовая проверка уже сделана — берём результаты `Checker`.
2. Сохраняем тип каждого выражения во время проверки (`exprTypes`).
3. Проходим по всем файлам, генерируем единый `.c`.
4. Убираем lifetimes (заменяем ссылки на указатели).
5. Мономорфизируем обобщённые функции и структуры по конкретным вызовам.
6. Все функции, кроме `main`, мангируем префиксом модуля.
7. Главная функция Rust `main()` компилируется как `blink_main()`, runtime-обёртка `int main(void) { return (int)blink_main(); }`.

## Представления типов в C

| Rust     | C                       |
|----------|-------------------------|
| `i32`    | `int32_t`               |
| `bool`   | `int` (`1`/`0`)         |
| `()`     | `int` (значение `0`)    |
| `String` | `const char*`           |
| struct   | `struct Name`           |
| enum     | `int` (константы)         |
| `[T; n]` | массив `T[n]`           |
| tuple    | сгенерированная struct  |
| `&T`     | `T*`                    |
| `&mut T` | `T*`                    |

## Модули
- Все файлы собираются в один C-файл.
- Имя функции/структуры формируется как `module__name` для не-корневых модулей.
- Вызовы `helper::greet()` становятся `helper__greet()`.

## Методы
- `impl` функции превращаются в обычные C-функции с первым параметром `self`.
- Вызов `p.distance()` → `Point__distance(&p)`.
- Статические методы `Point::new(...)` → `Point__new(...)`.

## Traits
- Пока что trait-методы разрешаются статически (monomorphизация).
- Для каждого вызова `p.print()` находим конкретный impl и генерируем специализацию.

## Generics
- При обходе AST собираем все конкретные инстанциации.
- Манглированное имя: `identity_i32`, `make_pair_i32_bool`.

## Блоки-выражения
- Используем `({ ...; expr; })` из TinyCC.

## Константы и static
- `const` → `#define`.
- `static` → глобальная переменная.

## Макросы
- `macro_rules!` разворачиваются в codegen по таблице макросов.

## Команды CLI
- `blink build <path>` — создать `<path>/../build/out`.
- `blink run <path>` — собрать и выполнить, вернуть exit-код.

## Тесты
- End-to-end: `blink build` на `testdata/phase*/valid` должен успешно собрать бинарь.
- Run-тесты: программы с `fn main() -> i32 { N }` должны завершаться с кодом `N`.

## Критерии приёма
- `go build ./...`, `go vet ./...` чисты.
- `GOMEMLIMIT=1GiB go test ./...` проходит.
- Компиляция фаз 1–11 через `blink build` успешна.
