# Поддержка Cargo-layout для Bevy

## Контекст

Команда `blink check bevy` не находит корневой Rust-файл, потому что текущий загрузчик ищет `main.rs` и `lib.rs` только непосредственно в переданной директории. Реальные Cargo-проекты, включая Bevy, размещают корневой файл в `src/main.rs` или `src/lib.rs`.

## Цель

Разрешить `blink check` и `blink build` принимать корень Cargo-проекта и автоматически выбирать `src/main.rs` или `src/lib.rs`, сохранив прежний режим для директории с корневым файлом непосредственно в ней.

## Что изменится

1. `cmd/blink/main.go` — поиск корневого файла в переданной директории и в её `src/`.
2. `cmd/blink/main_test.go` — регрессионные тесты для Cargo-layout.

## Детали реализации

1. Сначала искать `main.rs` и `lib.rs` в переданной директории в существующем порядке приоритета.
2. Если корневой файл не найден, искать `src/main.rs`, затем `src/lib.rs`.
3. Передавать директорию расположения корневого файла в загрузчик модулей, чтобы относительные `mod foo;` разрешались относительно `src/`.
4. Не загружать файлы из `target/`, `examples/` и других несвязанных каталогов автоматически.
5. Сохранить ошибку `no root .rs file` для директорий без поддерживаемого layout.

## Критерии приёмки

- [ ] `blink check` на директории с `src/lib.rs` находит корневой файл.
- [ ] `blink check` на директории с `src/main.rs` находит корневой файл.
- [ ] Относительный `mod foo;` из `src/lib.rs` загружается из `src/foo.rs`.
- [ ] Существующие тесты и прямой layout продолжают работать.
- [ ] `go test`, `go vet` и `go build` проходят.
