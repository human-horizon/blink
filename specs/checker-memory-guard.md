# Защита checker от чрезмерного потребления памяти

## Контекст

`GOMEMLIMIT` является мягким ограничителем. На большом crate Bevy RSS checker вырос до гигабайтов и продолжал работать, несмотря на установленный предел.

## Цель

Ограничить cold-check через настраиваемый `BLINK_MEMLIMIT` и завершать CLI до неконтролируемого расхода памяти.

## Что изменится

1. `cmd/blink/main.go` — разбор лимита, установка Go memory limit и watchdog живой heap.
2. `cmd/blink/main_test.go` — тест разбора значений лимита.

## Детали реализации

1. Поддержать значения `MiB` и `GiB` в `BLINK_MEMLIMIT`.
2. При заданном лимите перед запуском команды устанавливать `runtime/debug.SetMemoryLimit`.
3. Периодически проверять `runtime.MemStats.HeapAlloc`.
4. При превышении лимита завершать процесс с ненулевым кодом и диагностикой.
5. По умолчанию использовать безопасный лимит 1 GiB для CLI; библиотечный checker не ограничивать.

## Критерии приёмки

- [ ] `BLINK_MEMLIMIT=512MiB` корректно распознаётся.
- [ ] Некорректное значение даёт понятную ошибку.
- [ ] CLI не допускает бесконтрольный рост heap выше лимита.
- [ ] Существующие команды и тесты не ломаются.
- [ ] `go test`, `go vet` и `go build` проходят.
