# Остановка разбора после ошибки во вложенном модуле

## Контекст

При разборе inline-модуля `parseModDecl` продолжает цикл после ошибки дочернего `parseDecl`. Поскольку `parseDecl` после первой ошибки больше не продвигает токен, цикл зависает и на больших файлах приводит к чрезмерному потреблению памяти.

## Цель

Гарантировать продвижение или остановку всех parser-циклов после ошибки, начиная с inline-модулей.

## Что изменится

1. `internal/parser/parser.go` — остановка цикла тела inline-модуля при `p.err`.
2. `internal/parser/parser_test.go` — регрессионный тест.

## Детали реализации

1. Добавить условие `p.err == nil` в цикл разбора объявлений inline-модуля.
2. Сохранить первую диагностическую ошибку без попытки продолжить повреждённый AST.
3. Не менять поддержку корректных inline-модулей.

## Критерии приёмки

- [ ] Ошибка в inline-модуле возвращается за ограниченное время.
- [ ] Парсер не зацикливается после ошибки.
- [ ] Корректный inline-модуль продолжает разбираться.
- [ ] Все тесты, `go vet` и `go build` проходят.
